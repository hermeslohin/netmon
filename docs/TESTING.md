# netmon testing guide

How netmon is tested: what the unit and end-to-end (E2E) suites cover, how they are isolated from the live system, how to run them, and how to add tests.

- **Requirements ↔ tests mapping:** [TEST_TRACEABILITY.md](TEST_TRACEABILITY.md). It is generated, so don't edit it by hand.
- **Requirement catalog:** `tests/requirements.py`. Every requirement has an ID (`AUTH-02`, `AC-03`, …) and the doc it comes from (README, ACCESS_CONTROL, RISK_SCORING, CORRELATION, SETUP, USER_GUIDE).

## 1. Running the tests

```bash
cd ~/netmon
/usr/bin/python3 tests/run_tests.py            # everything (unit + e2e), refreshes the docs
/usr/bin/python3 tests/run_tests.py unit -v    # unit only, verbose
/usr/bin/python3 tests/run_tests.py e2e        # end-to-end only
/usr/bin/python3 tests/gen_docs.py --check     # CI gate: every test tagged, every requirement covered
```

You can also use plain `unittest`: `python3 -m unittest discover -s tests/unit -t tests` (or `-s tests/e2e`).

What you need: Python 3.12 with the standard library only, plus `openssl` on the PATH. The E2E harness uses `openssl` to make a throw-away TLS certificate. Nothing needs pytest, node or a browser.

The runner exits 0 when every test passes. Expected failures are allowed, because they document known bugs (see §6). After the tests it does three things:
1. It writes `tests/.last_results.json`, with the status of every test id.
2. It regenerates `docs/TEST_TRACEABILITY.md` with those statuses, and refreshes the inventory block at the end of this file.
3. It runs an **isolation check**. Tracked files outside `tests/` and the live DB backups in `baseline/backup/` must be unchanged by the run. If they changed, the runner prints a WARNING and exits 1.

### In `ship.sh`

Every `./ship.sh "msg"` runs the test gate as **step 0**, before the security scan and before anything is staged:

| Step | What happens | On failure |
|---|---|---|
| 0 | `tests/run_tests.py all` (log in `baseline/tests-last.txt`) | exit 7: lists the failing tests; nothing is committed |
| 0 | `tests/gen_docs.py --check` (traceability) | exit 8: an untagged test, an unknown REQ id or a requirement with no test |
| 3 | the commit message gets a `Tests: Ran N tests … OK` line | — |
| 5 (only with `--deploy`) | the read-only container checks run against the redeployed dashboard (log in `baseline/tests-deploy.txt`) | exit 9: a warning only, because the push has already landed |

`--force` does **not** skip the tests. In an emergency, `--skip-tests` does; the commit then says `Tests: not run (--skip-tests)`. The docs regenerated by the run (`TEST_TRACEABILITY.md` and the inventory below) are committed together with the change.

## 2. Isolation: the tests never touch live data

Every test module imports `tests/_env.py` first, before any netmon module. It points the environment at a temporary directory:

| Variable | Test value | Why |
|---|---|---|
| `STATE_DIR`, `NETMON_DB` | `<tmp>/state`, `<tmp>/state/netmon.db` | never the live `dashboard/state/netmon.db` |
| `NETMON_LLM` | `off` | no local model server calls and no event reviewer threads |
| `NETMON_INTEGRATIONS` | `<tmp>/state/integrations.json` | no Elasticsearch or UniFi credentials, so no network |
| `NETMON_BACKUP_DIR` | `<tmp>/backup` | `analyze.py` calls `store.backup()`, which writes to the **live** `baseline/backup/` by default |
| `NETMON_DIR` | the checkout | code only; `data/*.json` paths resolve to docs in the temp DB |

The temp directory is deleted when the tests exit. To keep it for debugging, set `NETMON_TEST_KEEP=1`. `_env.fresh_db()` empties the temp DB, except the `meta` table, and clears the store and site caches.

**Test data.** `tests/fixtures.py` builds synthetic, site-neutral data:
- Snapshots have the same shape `collect.py` writes.
- Addresses are in `10.0.0.0/8` or the RFC 5737 documentation ranges.
- MAC addresses are generated at run time with `fixtures.mac(i)`.

As a result, no literal MAC, site IP or host name gets into git, and `ship.sh`/`repo_guard.py` stay clean.

## 4. End-to-end tests (`tests/e2e/`)

E2E tests run netmon the way production does: as separate processes that talk over the network.

**Harness** (`tests/e2e/harness.py`):
- `Server` starts the real `dashboard/app/server.py` with:
  - its own temp state dir,
  - a fresh self-signed certificate made with `openssl`,
  - a free port,
  - the LLM off,
  - an admin seeded from `DASH_USER`/`DASH_PASS`.

  It waits for `/healthz` before the tests start and stops the process when they finish. Code passed as `seed=` runs inside the server's environment before the server starts, for example to write snapshots.
- `Client` is a small HTTPS client with a cookie jar. It sends the dashboard's CSRF header (`X-Netmon: 1`).

| File | Scenario |
|---|---|
| `test_e2e_dashboard.py` | **Transport:** TLS 1.2 or later (TLS 1.1 refused), security headers on every kind of response, `/healthz`. **Sign-in:** cookie flags, generic error messages, throttling per client (via `CF-Connecting-IP`), logout, tampered cookies, CSRF guard, malformed JSON. **Pages:** build-hash stamping, path traversal, 404s, gzip. **API:** every data view returns JSON with the LLM off; risk scores stay in 0–100; seeded findings reach correlation and Open events. **Check-offs:** round trip. **Password change:** self-service change revokes other sessions and stores an account alert. |
| `test_e2e_access_control.py` | **Roles:** the full role matrix, using accounts created through the admin API. A User is limited to the allow-lists; a defender can read everything but can't change settings. **User scope:** only the user's devices' alerts, a reduced site config, locked prefs, a private read marker. **User admin:** validation, least-privilege default, a role change applies on the next request, no self-demotion, deleting a user revokes their session, password reset. **Audit trail:** POSTs, failed logins and 403s are spooled with secrets redacted; the spool file and the DB are 0600. |
| `test_e2e_pipeline.py` | **`analyze.py`** over five daily snapshots: the baseline seeds and then becomes ready, a day-5 upload spike is flagged and keyed by MAC, steady devices aren't flagged, history is appended, and the backup lands in the sandbox. The dashboard then serves that output. **Server lifecycle:** the first start seeds the admin and later starts ignore the env vars; accounts without a role are migrated to admin; console `set-role` (the last admin is protected); `add-user` reads the password from a pty; the server starts with the LLM off. **CLIs:** `store.py check/stats`, `scheduler.py status`, `repo_guard.py`. |
| `test_e2e_container.py` | **The deployed container, read-only.** `docker inspect` shows a read-only root filesystem, a non-root user, `cap-drop ALL`, no-new-privileges and a healthy healthcheck. The live `/healthz`, `/login` and the 401 for unauthenticated requests all answer. These tests skip themselves when docker or the container isn't present. |

| test_e2e_alerts.py | Real server seeded with alarms, held watcher detections, mute-cleared and suppressed alerts, registry devices and AI verdicts: feed order/limit/hidden rows, my-devices mine flags (defender), User scope with cleared/held/extra ignored, extra=1 verdicts, held=1 detections and v= filter, cleared view rule names, mute rules list and remove (defender) restoring alerts, private vs shared read markers, page script per role |
| `test_e2e_open_events.py` | Real server with a seeded store: /api/events/open order, collapsed and merged rows, type/sev/q filters, default 2000 / cap 5000 / limit=0, check-off and restore via /api/acks, /detail, /inputs, /related (12-member cap), admin+defender 200 / user 403 / anonymous 401; two expected failures for negative and non-numeric limit (OE-03..OE-05, OE-07, OE-09, OE-11..OE-14, OE-17, OE-18) |
| `test_e2e_posture.py` | One server seeded with two nightly snapshots + one collected range: `/api/snapshot?id=latest` carries every Posture box; `/api/snapshots` order and 404s; range follows its nightly report (`base`); `/api/section` slicing; `/api/range` nightly window vs no broker (400) (POS-01, POS-02, POS-04..POS-06) |
| `test_e2e_posture.py` | Segmentation and IDS suppress rules via `/api/llm/review-limits` hide rows in every snapshot and range, removal restores them; invalid rules 400 (POS-07, POS-09, POS-10, POS-20) |
| `test_e2e_posture.py` | Check-offs (single and bulk `seg`) persist across nightly reports and ranges and are shared between accounts; User role gets 403 on snapshot/section/acks/suppress/range, defender can edit rules (POS-11, POS-12, POS-19) |

**Deliberately not covered by E2E:**
- the live Elasticsearch and UniFi collectors (`collect.py`, `extras.py`, `unifi.py`, `hosts.py`),
- real LLM calls,
- real Web Push delivery,
- `ship.sh`, which commits and pushes.

These need live credentials or have external side effects. Their logic is unit-tested, and the network edge is stubbed.

## 5. Writing a new test

1. Put the test in `tests/unit/test_<module>.py` or `tests/e2e/test_e2e_<scenario>.py`. The first lines must be:
   ```python
   import os, sys
   sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
   import _env  # noqa: E402   - isolation, before any netmon import
   ```
2. Give the class a one-line docstring. Give each test a docstring whose first line says what it verifies in plain English, followed by a `REQ:` line:
   ```python
   def test_user_cannot_check_off(self):
       """A User gets 403 when checking an item off.
       REQ: AC-03"""
   ```
3. When you add a feature, add its requirement to `tests/requirements.py` first. `gen_docs.py --check` fails if any requirement has no test, or if any test has no tag or an unknown tag.
4. Restore anything you monkeypatch, and use `_env.fresh_db()` when you need an empty store. Don't put literal MACs, site IPs or realistic secrets in test files.
5. When you add a setting (a settings endpoint, an Integrations section, a Settings-page key or a `set_*`/`put`/`save` function), add it to `tests/settings_inventory.py` with the requirements that cover it. `test_settings_inventory.py` fails until you do, and fails while any listed setting has no test.
6. Run `tests/run_tests.py`. It refreshes both docs, including the generated **Settings coverage** table.

## 6. Known bugs documented by tests

These tests are marked `@unittest.expectedFailure`. Once a bug is fixed, the runner reports **UNEXPECTED PASS**; remove the decorator then.

| Test | Bug |
|---|---|
| `test_correlate` – `test_fnv_matches_js_for_astral_characters` | `correlate.fnv` hashes code points, but `app.js` hashes UTF-16 code units. An alarm title containing an emoji therefore gets a different event id in Python than in the browser. Fix: hash UTF-16 units, as `corr_llm._fnv` does. |
| `test_store` (cfg round trip) | `cfg_flatten`/`cfg_build` lose a top-level empty-string key. Minor. |
| `test_analyze` – `test_value_equal_to_floor_counts` | `analyze.spike()` uses `>`, but `extras.SPIKE_COMMON` documents "at least min". |
